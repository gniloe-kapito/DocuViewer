# 📄 DocuViewer — клиентский просмотрщик документов

Полностью **клиентский** веб-просмотрщик документов: PDF, DOCX, XLSX/XLS/CSV, PPTX,
TXT, Markdown, JSON (включая JSONL), RTF и изображения. **Все файлы обрабатываются
прямо в браузере — ничего не отправляется на сервер.** Ни одного бэкенда: сайт можно
размещать как статику (GitHub Pages, любой CDN, локально).

---

## ✨ Возможности

### Поддержка форматов

| Формат | Библиотека | Что умеет |
|---|---|---|
| **PDF** | pdf.js | постраничный рендер, зум, поворот 90°, поиск по тексту, панель миниатюр, оглавление, переход к странице, печать, экспорт в PDF |
| **DOCX** | docx-preview | близкий к оригиналу рендер (стили, таблицы, изображения), постраничная навигация, миниатюры, поиск, печать, экспорт |
| **XLSX / XLS / CSV** | SheetJS | таблица, переключение листов, закрепление колонок, поиск по ячейкам, копирование CSV |
| **PPTX** | JSZip | просмотр по слайдам, лента миниатюр, навигация, полноэкранный режим, экспорт |
| **TXT** | — | текст, нумерация строк, перенос слов, статистика, поиск |
| **Markdown** | markdown-it + highlight.js | рендер с подсветкой кода, режим «Источник / Превью», поиск |
| **JSON / JSONL** | — | форматирование с подсветкой синтаксиса, свёртка, поиск |
| **Изображения** | — | JPG / PNG / GIF / WebP / SVG / BMP, зум, поворот 90°, ночной режим |
| **RTF** | — | упрощённый парсер с базовым форматированием |

### Универсальная оболочка просмотра (все форматы)

- 🔍 **Поиск по документу** — подсветка совпадений, счётчик «N / M», навигация
  Enter / F3 / Shift+F3 (доступен в 8 из 9 просмотрщиков).
- 🖼 **Панель миниатюр** — сворачиваемая, текущая страница подсвечена, клик —
  плавный переход.
- ℹ️ **Панель метаданных** — имя, размер, расширение, MIME-тип, дата изменения.
- ➕➖ **Зум** −/% /+ / сброс, `Ctrl + колесо мыши`, поворот на 90° (PDF, изображения).
- 🖨 **Печать** (`Ctrl+P`) и **«Скачать как PDF»** (html2canvas + jsPDF, целиком
  на клиенте).
- 🌗 **Ночной режим** (`N`) — инверсия «бумаги» документа с сохранением цветов
  маркеров поиска; работает во всех просмотрщиках, запоминается.
- 🖥 **Полноэкранный режим** (`F`) для любого просмотрщика.
- 📑 **Нумерация страниц** — поле ввода «стр. / всего» + кнопки ←/→ + Enter.
- ⚡ **Виртуализация больших PDF** — рендер только видимого окна страниц
  (документы на сотни страниц не съедают память).

### Работа с файлами

- 🖱️ **Drag-and-drop** — крупная зона по центру + кликабельные карточки форматов
  (открывают диалог с фильтром по расширению).
- 🗂 **Вкладки** — сколько угодно файлов одновременно, перетаскивание для
  изменения порядка, закрытие с возможностью восстановления (`Ctrl+Shift+T`).
- 🔗 **Открыть по URL** — загрузка файла по ссылке.
- 📜 **История** последних файлов в localStorage (только метаданные, не содержимое).
- ⚔️ **Режим сравнения** — два файла рядом с синхронизацией скролла
  (для одинаковых форматов), выход по `Esc`.
- 📋 Вставка файлов из буфера обмена (`Ctrl+V`).

### Интерфейс

- 🌗 Светлая / тёмная / системная тема.
- 📱 Адаптивная вёрстка (мобильные и десктоп).
- 🇷🇺 Полностью русскоязычный интерфейс.

### Горячие клавиши

| Клавиши | Действие |
|---|---|
| `Ctrl+O` | открыть файл |
| `Ctrl+V` | вставить файл из буфера |
| `Ctrl+F` | поиск по документу |
| `F3` / `Shift+F3` / `Enter` | следующее / предыдущее совпадение |
| `Ctrl+P` | печать |
| `F` | полноэкранный режим |
| `N` | ночной режим |
| `+` / `-` / `0` | зум больше / меньше / сброс |
| `←` `→` `Home` `End` | навигация по страницам |
| `Ctrl+колесо` | плавный зум |
| `Esc` | выход из полноэкранного режима / сравнения |

## ⚠️ Ограничения

- **Большие файлы** обрабатываются медленнее — весь парсинг идёт в браузере
  (вне основного потока для PDF).
- **PPTX**: анимации, переходы и точное форматирование не воспроизводятся —
  показывается текст и изображения по слайдам.
- **DOCX**: docx-preview отображает документ близко к MS Word, но отдельные
  сложные элементы (например, кликабельное оглавление) могут выглядеть
  упрощённо; при отклонениях показывается ненавязчивый значок.
- Изображения не поддерживают текстовый поиск (по самой природе формата).
- Старые бинарные форматы **.doc / .ppt** не поддерживаются — пересохраните
  файл в современном OOXML (.docx / .pptx).

## 🚀 Быстрый старт (локально)

Нужен [Bun](https://bun.sh) ≥ 1.2 (или npm/yarn — команды аналогичны):

```bash
bun install        # установить зависимости
bun run dev        # http://localhost:3000
```

Дополнительные команды:

```bash
bun run lint       # проверка ESLint
bun run typecheck  # проверка типов TypeScript
bun run build      # статическая сборка в папку out/
bun run preview    # локально отдать собранный out/ на :3000
```

## 📦 Сборка статической версии

Приложение не использует бэкенд, поэтому собирается в чистую статику
(`output: 'export'` → папка `out/`):

```bash
# Пример для репозитория github.com/<user>/my-doc-viewer
STATIC_EXPORT=1 NEXT_PUBLIC_BASE_PATH=/my-doc-viewer bun run build
# Результат — папка ./out/
```

`NEXT_PUBLIC_BASE_PATH` должен совпадать с путём, по которому сайт доступен
(для GitHub Pages — `/<имя-репозитория>/`). Для корневого домена оставьте пустым.

> 💡 Скрипты используют синтаксис окружения `VAR=value command` (bash/zsh).
> На Windows запускайте из WSL или Git Bash.

## 🌐 Развертывание на GitHub Pages (автоматически)

В репозитории есть workflow **`.github/workflows/deploy.yml`**, который:

1. Срабатывает при пуше в ветку `main` (или `master`) и по ручному запуску.
2. Устанавливает [Bun](https://bun.sh) и зависимости по `bun.lock`
   (`--frozen-lockfile`).
3. Вычисляет `NEXT_PUBLIC_BASE_PATH` по имени репозитория.
4. Собирает статический экспорт в папку `out/`.
5. Публикует её содержимое в ветку `gh-pages`
   ([peaceiris/actions-gh-pages](https://github.com/peaceiris/actions-gh-pages)).

### Как включить (один раз)

1. Запушьте проект в репозиторий GitHub (ветка `main`).
2. Дождитесь зелёного раннера во вкладке **Actions** — появится ветка `gh-pages`.
3. Откройте **Settings → Pages** → **Build and deployment → Source**:
   выберите **Deploy from a branch** → ветка **`gh-pages`** → папка **`/ (root)`** → **Save**.
4. Через минуту сайт будет доступен по адресу
   `https://<username>.github.io/<repo-name>/`.

### Заметки о деплое

- **Кастомный домен**: удалите шаг «Compute base path» и переменную
  `NEXT_PUBLIC_BASE_PATH` — basePath не нужен для корневого домена.
- **Vercel / Netlify**: проект тоже можно задеплоить туда — выберите
  Next.js-проект и команду сборки `bun run build:static` (артефакт `out/`),
  либо просто отдайте папку `out/` как статику.

## 📋 Как использовать эту папку

Содержимое репозитория самодостаточно — скопируйте его в новый пустой
GitHub-репозиторий:

```bash
# Вариант 1: новый репозиторий из этой папки
git init
git add .
git commit -m "DocuViewer — client-side document viewer"
git branch -M main
git remote add origin https://github.com/<username>/<repo-name>.git
git push -u origin main

# Вариант 2: скопировать файлы в уже созданный пустой репозиторий
cp -r . /path/to/your-repo/
```

После пуша workflow соберёт и опубликует сайт автоматически (см. выше).

## 🛠 Технологии

- **Next.js 16** (App Router, статический экспорт) + **TypeScript 5** + **React 19**
- **Tailwind CSS 4** + **shadcn/ui** (New York) + иконки **lucide-react**
- **next-themes** — темы; **zustand** — состояние UI и история
- Просмотрщики: `pdfjs-dist`, `docx-preview`, `xlsx` (SheetJS), `jszip`,
  `markdown-it`, `highlight.js`
- Экспорт в PDF: `html2canvas-pro` + `jspdf`

## 🔒 Приватность

DocuViewer не делает ни одного сетевого запроса с содержимым ваших файлов.
Единственный внешний запрос — загрузка воркера pdf.js с CDN (jsDelivr) для
рендеринга PDF: передаётся только код воркера, данные файла остаются в памяти
браузера. Весь парсинг и рендеринг происходят локально. История хранит только
метаданные (имя, размер, дату), не содержимое, и остаётся в вашем браузере.
